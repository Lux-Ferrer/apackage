## 2. 页面与交互流程

### 2.1 项目列表 `/projects/`

表列：项目编号 · 房屋名称 · 房屋地点 · 检测日期 · 记录数 · 操作。

- 「记录数」显示 `立柱3·横梁2`，由一条带子查询的 SQL 算出，不做 N+1 查询；
- 操作列：详情 / 编辑 / 删除；删除走应用内确认弹窗；
- 空态：引导「新建第一个项目」。

### 2.2 新建 / 编辑项目

字段与 `projects` 表一一对应：项目编号（必填、唯一）、房屋名称（必填）、房屋地点、委托单位、检测日期（`YYYY-MM-DD`）。

- 项目编号重复时**在字段下方就地报错**并保留已填内容（不返回 500）；
- 新建成功后 302 跳**项目详情页**（下一步大概率是加检测记录）。

### 2.3 项目详情 `/projects/<pid>` —— M1 主界面

- 顶部：项目信息 + 「编辑项目 / 删除项目」；
- 记录区标题：`检测记录（立柱 3 条 · 横梁 2 条）` + 「添加检测记录」；
- 记录按模板分成**立柱 / 横梁两个区块**（立柱在前，与真实报告一致）；
- 每条记录默认折叠，摘要行为 `模板 · 楼层 · 构件位置 · 尺寸结果 · N 个面(B/H)`，点击展开厚度明细表；
- **展开的明细表与 Word 导出表同构**（检测面 + 1~5 + 最小值），所见即所得；
- 明细里的最小值由服务端计算后渲染，不依赖前端；
- 底部：关联缺陷报告（见 §5.2）。

用 `<details>/<summary>` 实现展开折叠，无 JS 也能工作。

### 2.4 模板选择页

两张卡片（幕墙立柱 / 幕墙横梁），各自展示模板名与建议检测面；点击进入记录表单。服务端对 `template` 做白名单校验。

### 2.5 检测记录表单（新增 / 编辑共用）

```
模板：幕墙立柱截面尺寸检测结果        ← 编辑时为只读徽标
── 构件信息 ──
楼层 / 构件位置 / 尺寸结果 / 截面尺寸要求（下拉）
── 厚度检测（每个检测面 5 个读数）──
┌────────┬────┬────┬────┬────┬────┬────────┬──┐
│ 检测面 │ 1  │ 2  │ 3  │ 4  │ 5  │ 最小值 │  │
└────────┴────┴────┴────┴────┴────┴────────┴──┘
[+ 添加检测面]（最多 6 个）
```

## 3. 层级结构：构件 → 检测面 → 5 个读数

数据库是两层：`measurement_records`（= 一个构件）挂 `thickness_readings`（= 一个检测面）。界面上用**同一张表**表达：构件信息是表头区，每个检测面是表里一行。

这样设计与真实报告「一行 = 楼层|构件位置|尺寸结果|检测面|1|2|3|4|5|最小值|要求」同构，用户不需要做映射。

### 表单字段命名约定

| 界面元素 | 提交字段名 |
| --- | --- |
| 楼层 / 构件位置 / 尺寸结果 | `floor` / `member_position` / `size_result` |
| 截面尺寸要求（下拉） | `requirement_index`（序号，服务端解析成文案快照） |
| 第 i 个检测面的面标签 | `face_<i>` |
| 第 i 个检测面的第 k 个读数 | `value_<i>_<k>` |

- 服务端固定探测 `i = 0..FACE_MAX_COUNT-1`（常量 6），**不信任前端提交的行数**；
- 整行空白（面为空且 5 个读数全空）直接跳过，"加了一行又没填"不产生脏数据。

### 前端实时计算最小值

| 项 | 设计 |
| --- | --- |
| 触发 | 该行任一读数输入框的 `input` 事件（输入、粘贴、清空都覆盖） |
| 规则 | 解析为数字，忽略空白与非数字；至少 1 个有效值才显示；保留 **2 位小数**；全空显示 `—` |
| 反馈 | 高亮持有最小值的输入框；无法解析的输入标红 |
| 展示 | 行内只读文本，**不参与提交** |
| 权威来源 | 保存与导出时由服务端 `services/thickness.face_min_text()` 重算 —— 前端只是预览，绝不信任客户端算出的值 |
| 降级 | 无 JS 时不显示最小值，表单照常可提交，保存后详情页可见正确结果 |
| 上限 | 最多 6 行，到上限后禁用「添加检测面」；每行可删除，至少保留 1 行 |
| 重复面 | 前端即时提示，服务端也校验（同记录内 `face` 唯一，DB 有 `UNIQUE` 兜底） |

## 4. 编辑锁定：模板类型不可切换

| 层 | 新增 | 编辑 |
| --- | --- | --- |
| 界面 | 由 `?template=` 决定 | 只渲染只读徽标，页面上不存在模板控件 |
| 下拉 | 加载该模板的截面要求条文 | 同样按记录自身的 `template_type` 加载，条文不会串台 |
| 路由 | `records.create` 从 query 白名单取 `template` | `records.edit/update` 无 template 参数，处理器不读表单里的 `template_type` |
| 数据 | INSERT 写入 | **UPDATE 语句字段清单不含 `template_type`**，伪造 POST 也改不掉 |

检测到伪造的不同 `template_type` 时**静默忽略**（保持幂等），不报错。

## 5. 记录数与关联报告

### 5.1 项目列表的「记录数」

一条 SQL 用子查询同时算出立柱数、横梁数，避免逐行再查。

### 5.2 项目详情的关联报告

- 标题 `关联缺陷报告（N 份）`，列表显示 缺陷类型 / 隐患等级徽标 / 工程部位 / 时间，按时间倒序；
- 无绑定时显示空态 + 说明「缺陷填报的『绑定项目』在 M3 实现」；
- **M1 只做只读展示**，绑定与附页导出属于 M3，M1 不依赖 M3 即可独立验收。

### 5.3 删除项目的影响提示

确认弹窗文案由实际数据拼出，与 DB 语义严格一致：

> 确认删除项目「金骐智谷（JCZG）」？将同时删除 5 条检测记录（立柱 3 条、横梁 2 条）；关联的 2 份缺陷报告将解除绑定并保留。

对应：检测记录 `ON DELETE CASCADE`，缺陷报告 `ON DELETE SET NULL`。

## 6. 服务端校验与事务

### 校验

| 对象 | 规则 |
| --- | --- |
| 项目 | `project_no` 必填、唯一（冲突给字段级友好提示）、长度上限；`house_name` 必填；`test_date` 若填必须是合法 `YYYY-MM-DD`；其余选填 |
| 记录 | `floor`、`member_position` 必填；`size_result` 选填（规范化 `×`）；至少 1 个检测面；面必填且记录内唯一；读数必须能解析为数字，留空合法；填了读数但面为空 → 报错 |

### 事务（重点）

- 新增：`INSERT measurement_records` → `INSERT thickness_readings`，**同一事务**；
- 编辑：`UPDATE measurement_records`（不含 `template_type`）→ `DELETE` 该记录全部读数 → 重新 `INSERT`，**同一事务**；
- 任一步失败（含 `UNIQUE(record_id, face)` 冲突）**整体回滚**，不留半条记录、不丢原有读数；
- 统一由 `db.transaction()` 上下文管理器收口：块内抛异常 → `rollback` + 重新抛出，否则 `commit`；
- 编辑采用"删除重建"而非逐行 diff：逻辑简单、不漏行，`UNIQUE` 天然防重。

## 8. 验收标准

1. 能新建 / 编辑 / 删除项目；编号重复有友好提示；删除有二次确认且提示级联影响
2. 同一项目下能混合录入立柱与横梁记录
3. 每个检测面 5 个读数，前端实时显示最小值；保存后详情页展开的明细与将来 Word 导出内容一致
4. 编辑记录时模板类型改不掉（界面无控件、路由不接收、SQL 不更新）
5. 项目列表显示记录数；详情页显示立柱/横梁分类计数与关联报告区
6. 用 `docs/samples/检测结果案例.xlsx` 的立柱 10 行、横梁 5 行能完整录入
7. 新增测试，全套测试保持全绿
