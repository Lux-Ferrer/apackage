# 真机验证 checklist（UI 移动端改造）

> 目的：在真实手机上确认 UI 改造可用，**发现问题时先记录、不要边测边改**（一改就要重跑四条基线闸门）。
> 前置：`python app.py --lan`（见 README「手机真机验证」一节的 4 个前置条件）。
> 范围：只验 UI 与交互。Word 产物质量已在自动化闸门里锁着，不在本清单范围。

## 怎么用这份清单

1. 在电脑上执行 `python app.py --lan`，把终端打印的 `http://192.168.x.x:5000` 输进手机浏览器；
2. **先做 A 组**（能打开才谈得上后面的）；A 组不通就直接跳到文末「打不开怎么办」；
3. 按组往下走，每项都写明了**怎么算通过**；不通过的记下 **编号 + 截图 + 当时页面 URL**，连同手机型号与浏览器一起发我；
4. 全部走完大约 15~20 分钟；B 组（检测面录入）是本次改造的核心，值得多花两分钟反复点。

记录格式建议：

```
B6  失败  |  iPhone 13 / Safari 17  |  /projects/1/records/new?template=column
现象：填满 5 格后圆点还是黄色，进度显示 4/5
截图：IMG_0421.png
```

## 打不开怎么办（A 组不通时按顺序排查）

| 步骤 | 操作 | 结论 |
| --- | --- | --- |
| 1 | 电脑浏览器打开 `http://<局域网IP>:5000`（**用局域网 IP，不要用 127.0.0.1**） | 打不开 → 服务没绑对，重跑 `python app.py --lan` 看终端输出 |
| 2 | 电脑能开、手机不能 | 查：手机是否开着 VPN（关掉）→ 是否同一 Wi-Fi（看手机 Wi-Fi 详情里的 IP 前三段是否与电脑一致）→ 防火墙是否放行（见 README 前置条件 3） |
| 3 | 还是不行的公司网/访客网 | 极可能是路由器开了**客户端隔离**（AP Isolation）。用手机开热点、电脑连手机热点再试 |
| 4 | 都不行 | 换端口：`python app.py --lan --port 8080`（有些网络屏蔽 5000） |
