# M5 真机验证 checklist（纯前端 / 离线 / 图片管线）

> 与 `真机验证checklist.md` 的分工：那份验的是 **Flask 版 UI 改造**（`python app.py --lan`）。
> 这份验的是 **M5 的纯前端版**（静态页 + IndexedDB + docx JS）——风险点完全不同：
> 那边怕"按钮点不动"，这边怕**丢数据**（配额/持久化）、**照片方向不对**、**离线打不开**。
>
> ⚠️ **执行时机**：M5-4 把 UI 接到数据层之后才能跑。M5-3 只做到"图片管线 + 导出引擎"，
> 页面上还没有导入图片的入口 —— 但**下面 B 组（照片方向）是 M5-3 的验收判据**，
> 接线完成后必须优先跑完 B 组。
>
> 记录格式与那份一致：`编号 | 通过/失败 | 机型 / 系统 / 浏览器 | 现象 + 截图`。

## 前置

1. 起一个静态服务器指向 `web/`：`python -m http.server 8080 --directory web`
   （**故意用最朴素的静态服务器**：M5 的目标是"任何静态服务器都能跑"，不依赖 Flask 的路由/模板）。
2. 手机访问 `http://<电脑IP>:8080`（前置条件同 `真机验证checklist.md` 的 A 组排错条目）。
3. 若要用相机直接拍，**必须走 https 或 localhost**（浏览器只在安全上下文里给摄像头）。
   局域网 http 下只能用"从相册选择"——这是浏览器的限制，不是本工具的缺陷。
4. 准备好：一张**竖拍照片**（手机相册里通常都是）、一张**大图**（>1600px，最好 >3MB）、
   一张**横拍截图**。

## A. 存储与"会不会丢数据"（M5 最大的真实风险，5 项）

| # | 操作 | 通过判据 | 失败时记什么 |
| --- | --- | --- | --- |
| A1 | 首次进入 → 「我的 → 数据管理」 | 显示「已存储 x MB / y MB（z%）」；若**未获持久化授权**，必须显示**⚠️ 提示 + 「导出备份」入口**（不得静默通过） | 截图 |
| A2 | 点「申请持久化授权」 | 状态变成「已获持久化授权，系统不会自动清理数据」（iOS Safari：提示"添加到主屏幕"后才会授予，属预期） | 截图 |
| A3 | 连续导入若干张照片后回看 A1 | 已用空间**明显增长**（说明图片确实落在 IndexedDB 里，不是只存了路径） | 前后两张截图 |
| A4 | 关掉浏览器标签页 → 重新打开 | 数据仍在（项目 / 记录 / 报告 / 缩略图都在） | — |
| A5 | 手动把存储塞到接近上限（或把配额调到很小）再导入 | 出现**明确拦截**并引导"先导出备份再清理"，**不是**静默失败或白屏 | 截图 |

> A5 是这一组的重点：QuotaExceeded 在真实现场是会发生的，**提示必须能指导下一步动作**。

## B. 隐患照片的方向与清晰度（M5-3 的核心验收，5 项）

| # | 操作 | 通过判据 | 失败时记什么 |
| --- | --- | --- | --- |
| B1 | 导入一张**竖拍**照片（相册里的原图，带 EXIF 方向） | 列表缩略图与详情大图**都是正的**（不是躺倒/上下颠倒） | 截图（原图 + 页面） |
| B2 | 同上，导出 Word 后在**电脑**上打开 | 附页里的照片**方向正确**，且**没有被拉伸变形**（宽高比与原图一致） | 把 docx 发我 |
| B3 | 导入一张**横拍**照片 | 方向正确、宽高比正确 | 截图 |
| B4 | 导入一张**大图**（>1600px） | 附页信息表「图片文件」行显示 **`原名（已压缩）`**；图片按长边 1600px 嵌入、不变形 | 截图（附页那一行） |
| B5 | 导入一张**小图**（<1600px） | 「图片文件」行显示 **`原名`**（**不带**"已压缩"——没缩过就不该这么说） | 截图 |

> B1/B2 是这一组的重点。**注意**：B1 在浏览器里过不代表 B2 也过 ——
> 只有 B2 同时验了"摆正后的像素真的被写进 docx"。
> 自动化侧已覆盖到"尺寸/方向数学"（单测 + 闸门 A 的附页对拍），
> 但**真机竖拍照片**这条链只有这里能验。

## C. 图片缺失与降级（2 项）

| # | 操作 | 通过判据 |
| --- | --- | --- |
| C1 | 把某张已导入的照片在浏览器里清掉（DevTools → Application → IndexedDB → 删除该条 `images` 记录），再导出 Word | 附页**照样导得出来**，「图片文件」行显示 `原名（文件缺失）`，正文显示 `（图片缺失：原名）`，整份报告其它部分不受影响 |
| C2 | 同上，看报告列表 | 缩略图位置显示**占位块**（不是浏览器碎图图标），点击不报错 |

## D. 离线与 PWA（M5-5 交付，先在真机上确认边界，3 项）

| # | 操作 | 通过判据 |
| --- | --- | --- |
| D1 | 首次在线打开 → 断网 → 刷新页面 | 页面**仍能打开**（Service Worker 已缓存壳与资源），能查看已有数据 |

## 测完之后

- **B 组全通过** → M5-3 的图片管线可以判定"真机可用"，继续 M5-4 接线。
- **B1/B2 失败**（照片躺倒或变形）→ 记下机型 + 浏览器版本，这通常是
  `createImageBitmap({imageOrientation:'from-image'})` 不被支持、走到了 `<img>` 降级路径。
  把截图发我，我按 `web/app/image-pipeline.js` 里的 `orientationTransform` 矩阵逐项核对。
- **A 组失败**（提示缺失 / 静默失败）→ 属必修项：现场丢数据是不可接受的。
- 老规矩：**任何代码改动之后，四条基线闸门 + 两条 M5 闸门都要重跑**
  （命令见 README「测试」一节）。
