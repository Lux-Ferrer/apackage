## 2. 11 列固定列宽在 python-docx 里怎么实现

`doc.add_table()` 生成的 `tblGrid` 是**等宽**的、`tblW` 是 `auto`，都不合用。所以要三步接管：

1. `tblPr/tblW = 8800 dxa`、`tblPr/tblLayout = fixed` —— 固定布局的总宽与模式；
2. **替换** `tblGrid`，写入 11 个 `gridCol`（必须紧跟 `tblPr`，schema 顺序敏感）；
3. 每个单元格写 `tcPr/tcW`，跨列格写**跨列之和**（`厚度检测结果` 格 = 480 + 760×6 = 5040）。

**必须用 `docx.shared.Twips` 而不是 `Cm`**：Emu = twips × 635 是整数往返无损，而 `Cm(0.87).twips` 可能落到 493 —— 对拍会出现"列宽差 1"。

## 3. 合并的代码结构

### 3.1 布局规格（纯数据）与 XML 物化分离

- `Cell` / `Row`（dataclass）：一个逻辑单元格的 `text / width / span / vmerge / margin / bold / size / align / plain`；
- `_header_rows()` / `_member_rows()`：**纯数据**地组出行规格（可脱离 Word 单测）；
- `build_table(doc, rows, widths)`：物化成 OOXML。

### 3.2 横向合并（表头跨 7 列）

横向合并会让该行的 `w:tc` **数量减少**：

| 行 | `w:tc` 个数 |
| --- | --- |
| 表头 r0 | **5**（第 4 个 `gridSpan=7`、`tcW=5040`） |
| 表头 r1 | 11 |
| 数据行 | 11（纵向合并不减少数量） |

物化时先建 11 格的空行，再**删掉多余的 `w:tc`**，然后逐个写属性。

### 3.3 纵向合并（多面构件的四列）

| | 楼层 | 构件位置 | 尺寸结果 | 面 | 1~5 | 最小 | 截面尺寸要求 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 首个面 | **restart** | restart | restart | B | 读数 | 最小值 | **restart** |
| 后续面 | **continue（裸格）** | continue | continue | H | 读数 | 最小值 | **continue** |

- 行数 = **检测面总数**（一行一个面）；
- continue 裸格按样例实测规格：只有 `tcW + vMerge`，**不写 `tcMar`/`vAlign`**，段落是无 `pPr` 的 `<w:p/>`；
- **单面构件不写任何 `vMerge`** —— 这条是对拍抓出来的：一条 `restart` 本身不构成合并，但会让文档与样例产生无谓差异。

### 3.4 两个已避开的 python-docx 陷阱

| 陷阱 | 现象 | 做法 |
| --- | --- | --- |
| 用 `row.cells` 遍历 | 合并后会把被合并格**解析回起始格** | 一律遍历 `tr.findall(qn('w:tc'))` 拿原始元素 |
| 用 `cell.merge()` | 不动 `tblGrid`、不设 `vAlign`/`tcMar`、把两格文本拼接 | 不用 merge，显式建 `w:tc` + 显式 `gridSpan`/`vMerge` |

## 4. 对拍策略

### 4.1 三个基准

| # | 基准 | 职责 |
| --- | --- | --- |
| O1/O3 | 样例 docx | **版式**：从样例回灌它**自己的数据**后重新生成，逐属性全等比较（主闸门） |
| O2 | 案例 xlsx | **内容**：真实数据导出的表格与案例逐格比对（结构/数值） |
| O4 | 需求报告 | **条文文字**：config 的条文与需求报告归一化后一致 |

### 4.2 比对属性

文档 `sectPr`（pgSz/pgMar/cols/docGrid）；正文子元素顺序与类型、段落 text/jc/spacing、run 属性集合；
表格 tblW/jc/tblLayout/tblBorders(6 边)/tblCellMar/tblLook/tblGrid；
行 trHeight(val,hRule)/trPr jc；
单元格 `w:tc` 个数与顺序、tcW/gridSpan/vMerge/tcMar/vAlign、段落格式；
以及**合并结构的逻辑网格**（`^` 纵向被合并、`<` 横向被合并）。

### 4.3 明确忽略（各有理由）

| 忽略项 | 理由 |
| --- | --- |
| `w:rsid*` / `w14:paraId` / `w14:textId` / `w:proofErr` | Word 编辑痕迹，无语义 |
| XML 声明与属性顺序 | python-docx 重写为单引号 + LF（实测 styles.xml 仅此差异） |
| **run 的切分方式** | 样例把长条文按中英文字界拆成多个 run；文本按段落拼接后比较，run 只比属性集合 |
| 样例的玻璃章节 | 范围外；比较前从样例侧剔除，并反向断言生成物不含玻璃 |

### 4.4 浮点处理

| 层 | 规则 |
| --- | --- |
| 版式数值 | 整数 twips → **精确相等**；规格加载时断言无 float |
| 文本层 | 厚度读数/最小值在写入前已由 `thickness.format_mm()` 变成两位小数字符串 → **纯字符串比较**，天然无浮点误差 |
| 跨层数值（案例 `2.1` vs 报告 `2.10`） | 先 `format_mm(float(x))` 规范化两侧再比字符串，**禁止** `float == float` |
| 兜底 | 归一化后仍不等 → FAIL；归一化相等但原文不同 → **WARN**（案例 xlsx 是 OCR 转录，标点可能失真） |

## 5. 与 report_base.docx 底座的配合

实测：`theme1.xml` **逐字节一致**；`styles.xml` / `settings.xml` **内容一致**（仅 XML 声明的引号与换行不同）。
因此不写 `rFonts`、不写字号的地方，继承链与样例逐级相同 → 字体与默认字号自动对齐。

底座清空正文后**没有表格**，所以表格级属性必须自己写全（常量来自 §1）。

### M0 的 6 项回修（本次落地）

| # | 原状 | 改为 |
| --- | --- | --- |
| 1 | `write_cell()` 默认强制 11pt | 默认 `size=None` = **继承**；仅「要求」列数据格显式 8pt |
| 2 | 单元格段落写 `spacing=0/0` | **不写 spacing**（样例没有） |
| 3 | 正文段落一律零间距 | 按角色写样例间距（信息段 after=100、标题 300/200、空段 200/200、备注 300） |
| 4 | 加粗只写 `w:b` | 同时写 `w:bCs` |
| 5 | 没有表格后的空段落 | 每张表后补一个 `before/after=200` 的空段 |
| 6 | 无文末空段 | 文末保留一个空段落 |
| 7 | 尺寸结果 `63 164` → `63164`（静默损坏） | 两个数字之间的空白视作 `×` |
