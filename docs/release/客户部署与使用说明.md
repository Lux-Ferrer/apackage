# 客户部署与使用说明

**建筑幕墙检测报告工具 v1.0.1**
中冶建筑研究总院（深圳）有限公司

---

## 0. 先读这一页

| 问题 | 答案 |
| --- | --- |
| 需要装数据库吗？ | **不需要**。整个工具是静态网页，数据存在**每台设备的浏览器**里 |
| 需要联网吗？ | 部署时需要（第一次打开）；之后可以离线使用 |
| 服务器要什么？ | 一个能提供静态文件的 Web 服务：Nginx / IIS，或包内自带的 `serve_static.py` |
| 数据存在哪？ | 各设备的浏览器 IndexedDB，**不上传服务器**，多台设备之间**不共享** |
| 怎么防止数据丢？ | 「我的 → 数据管理 → 导出备份」定期导出（详见第 5 节） |
| 报告人名字怎么改？ | 每台设备在「我的 → 个人信息配置」填一次；或改出厂默认值（第 4 节） |

> ⚠️ **三条最容易踩的坑**（都会表现为"页面一片空白"）：
> 1. 服务器没把 `.mjs` 当 JavaScript 返回（IIS/Nginx 默认都没有这个类型）；
> 2. 双击 `index.html` 用 `file://` 打开（浏览器禁止这种页面用 IndexedDB 与模块）；
> 3. 用 `python -m http.server` 起服务（它同样不认识 `.mjs`）。请用包内的 `serve_static.py`。

## 1. 包里有什么

解压后是一个 `mcc-inspection-tool/` 目录：

```
mcc-inspection-tool/
├── index.html              入口页面
├── sw.js                   Service Worker（离线支持）
├── manifest.webmanifest    安装到主屏幕用的清单
├── 客户部署与使用说明.md     本文件
├── VERSION.txt             版本号 / 构建时间 / 离线缓存版本
├── serve_static.py         临时演示用的静态服务器（零依赖，需 Python 3.8+）
├── app/                    应用代码（视图 / 数据层 / 报告生成）
├── assets/                 报告底座模板、离线清单、版式规格
├── icons/                  主屏幕图标
├── styles/                 样式
├── vendor/                 第三方库（docx / jszip，已随包附带，**不联网下载**）
└── deploy/
    ├── nginx.conf.example  Nginx 配置示例
    └── web.config.example  IIS 配置示例
```

**浏览器要求**：Chrome / Edge 89 及以上、Safari 16.4 及以上（iOS 16.4+）、Firefox 108 及以上。
不支持 IE 与早期的国产浏览器内核（它们不支持 ES module 与 import map）。

## 2. 内网部署（三种方式，任选一种）

### 方式 A：Nginx（推荐）

```bash
# 1) 把包解压到服务器
sudo mkdir -p /var/www/mcc-inspection-tool
sudo tar -xzf mcc-inspection-tool-v1.0.1.zip -C /tmp
sudo cp -r /tmp/mcc-inspection-tool/* /var/www/mcc-inspection-tool/

# 2) 配置站点（示例文件在 deploy/ 里，已写好 MIME 与缓存策略）
sudo cp /var/www/mcc-inspection-tool/deploy/nginx.conf.example /etc/nginx/conf.d/mcc.conf
sudo vi /etc/nginx/conf.d/mcc.conf      # 把 root 改成真实路径，server_name 改成实际地址

# 3) 检查并生效
sudo nginx -t && sudo nginx -s reload
```

访问 `http://<服务器IP>/` 即可。

**配置里必须保留的三件事**（示例文件已包含）：

| 项目 | 为什么 |
| --- | --- |
| `.mjs` → `text/javascript` | 漏了浏览器会拒绝加载模块 → **白屏** |
| `.webmanifest` → `application/manifest+json` | 漏了"添加到主屏幕"拿不到图标与名称 |
| `sw.js` / `index.html` → `Cache-Control: no-cache` | 否则手机一直用旧版本，更新推不下去 |

> 本工具用 **hash 路由**（地址形如 `/#/projects`），所以**不需要**配置"未知路径回退到 index.html"。

### 方式 B：IIS（Windows Server）

1. IIS 管理器 → 网站 → 添加网站，物理路径指向解压后的目录，端口 80（或任意）；
2. 把 `deploy/web.config.example` 复制到站点根目录并改名为 **`web.config`**；
3. 浏览器访问 `http://<服务器IP>/`。

`web.config` 里做了两件事：补 `.mjs` / `.webmanifest` 的 MIME 类型，以及让入口文件不被长缓存。
如果报"无法添加重复的 mimeMap"，说明服务器级别已经配过，删掉对应那行即可。
IIS 没装 URL Rewrite 模块时，**删掉整个 `<rewrite>` 节**也能正常使用（只是更新后需要用户清一次站点数据）。

### 方式 C：临时演示 / 没有 Web 服务器

服务器或任意一台电脑上装了 Python 3 的话，在解压目录里执行：

```bash
python serve_static.py            # 默认 8080 端口，会打印"本机"和"手机"两个地址
python serve_static.py --port 9000
```

它会正确返回 `.mjs` 的 MIME、关闭缓存，并自动找出局域网 IP 打印出来。

> 这只是**演示/临时**用途：没有认证、没有 HTTPS、允许列目录。正式使用请用 Nginx 或 IIS。

## 3. 手机通过局域网访问

1. 手机与服务器（或那台跑 `serve_static.py` 的电脑）**连同一个 Wi-Fi / 同一网段**；
2. 手机浏览器地址栏输入 `http://<服务器IP>:<端口>/`
   （用 `serve_static.py` 时，终端里已经直接打印了"手机打开"那一行，照着输入即可）；
3. 打开后建议**添加到主屏幕**，当独立 App 用（前提见下面方框）。

> ### ⚠️ 「离线使用」和「独立 App 窗口」需要一个前提：HTTPS
>
> 浏览器规定：**只有安全上下文**（`https://` 或本机 `localhost`）才允许注册 Service Worker。
> 所以：
>
> | 访问地址 | 录入 / 导出 / 备份 | 离线使用 | 添加到主屏幕 |
> | --- | --- | --- | --- |
> | `http://<内网IP>:<端口>`（普通 http） | ✅ 全部可用 | ❌ 不可用 | 只能加"普通快捷方式"（打开仍是浏览器标签页） |
> | `https://<域名或IP>/`（内网证书） | ✅ 全部可用 | ✅ | ✅ 独立窗口、无地址栏 |
> | `http://localhost:<端口>`（只在本机测试时） | ✅ | ✅ | ✅ |
>
> **如果现场需要离线、或希望像 App 一样全屏使用，请给站点配 HTTPS**（内部 CA 签发的证书即可，
> 手机需信任该 CA）。只用内网 http 也没问题 —— 功能不受影响，只是没有离线能力。

### 添加到主屏幕

| 系统 | 步骤 |
| --- | --- |
| **iOS（Safari）** | 打开页面 → 底部「分享」按钮 → 「添加到主屏幕」→ 命名 → 添加 |
| **Android（Chrome）** | 打开页面 → 右上「⋮」→ 「安装应用」（HTTPS 下）或「添加到主屏幕」 |
| Android（国产浏览器） | 菜单里找「添加到桌面」（部分浏览器不支持离线缓存，建议用 Chrome） |

装到主屏后从桌面图标打开：**HTTPS 下是独立窗口（无地址栏）**；http 下只是一个快捷方式。
（实测：Android Chrome 在 HTTPS/localhost 下会创建"WebApp"，从图标启动不带浏览器界面、断网也能打开。）

### 让系统不要清掉数据（重要，尤其 iOS）

iOS Safari 对**未获"持久化授权"**的站点有约 7 天的闲置清理策略。到：

**我的 → 数据管理 → 申请持久化授权**，看到「已获持久化授权，系统不会自动清理数据」才算成功。
iOS 上可能要求**先把页面添加到主屏幕**再申请 —— 这是 iOS 的规则。

### 打不开怎么办

| 现象 | 排查方向 |
| --- | --- |
| 手机打不开、电脑能打开 | 电脑防火墙放行端口；手机是否连了 VPN；是否同一网段（IP 前三段相同） |
| 公司网络 / 访客网络打不开 | 路由器很可能开了**客户端隔离（AP Isolation）**：用手机热点、电脑连该热点再试 |
| 页面一片空白 | 见下方"常见问题"第 1 条（`.mjs` 的 MIME） |
| 打开很慢 | 首次要下载约 1.5MB 的库文件，之后走本地缓存 |

## 4. 修改默认报告人 / 产品信息

### 4.1 推荐方式：在界面里填（每台设备各自一次）

**我的 → 个人信息配置** → 填写「报告人姓名」「部门」→ 保存。

- 保存后，**之后新填写**的缺陷报告与 Word 附页都会用这个署名；
- 已经保存过的报告里存的是当时的快照，**不会被改动**（历史报告保持原样，这是有意的）；
- 这项设置存在**该设备**的浏览器里：换手机、换浏览器、清站点数据后需要重填；
  它也**不随备份文件迁移**。

### 4.2 改出厂默认值（新设备第一次打开时生效）

用任意文本编辑器打开 **`app/product.js`**，改这两行：

```js
export const DEFAULT_PROFILE = Object.freeze({
    reporter_name: '检测员',
    reporter_department: '检测部',
});
```

改完保存即可。已经是老用户的设备上，界面里保存过的值**优先**于这里。

> ⚠️ 不要改 `app/config.js` —— 那是构建产物，里面虽然也有 `DEFAULT_REPORTER`，
> 但界面不读它，改了不会生效（下次构建还会被覆盖）。

### 4.3 同时可以改的产品信息（同一个文件 `app/product.js`）

```js
export const PRODUCT = Object.freeze({
    name: '建筑幕墙检测报告工具',
    name_en: 'Curtain Wall Inspection Report Tool',
    version: '1.0.0',                                  // 改这里要同步改包名
    vendor: '中冶建筑研究总院（深圳）有限公司',
    support: '',                                       // 填了会在"关于"页显示技术支持
});
```

### 4.4 改完必须让手机更新缓存

本工具用 Service Worker 做离线缓存，改了文件后：

1. 电脑上重新部署（覆盖文件）；
2. 手机**关掉页面重新打开** —— 会提示「新版本已下载，关闭本页再打开即可用上」；
3. 到 **我的 → 关于 → 「离线缓存版本」**，确认那 12 位十六进制**变了**。

没变就说明还是旧版本（浏览器/SW 缓存未更新）。必要时在浏览器里清除该站点数据后重新打开。

## 5. 数据、备份与恢复

**数据在哪里**：每台设备的浏览器（IndexedDB）。服务器上**没有**任何数据，
所以换设备、清理浏览器数据、卸载浏览器都会让数据消失。

**必须养成的习惯**：定期导出备份。

| 操作 | 位置 | 说明 |
| --- | --- | --- |
| 导出备份 | 我的 → 数据管理 → 导出备份（.zip） | 含全部项目、检测记录、缺陷报告、**原始照片** |
| 恢复备份 | 我的 → 数据管理 → 导入备份 | **覆盖**当前全部数据（会先让你确认覆盖什么） |
| 查看占用 | 我的 → 数据管理 | 已用空间 / 配额，以及是否已获持久化授权 |
| 清除报告 | 我的 → 数据管理 → 清除全部报告 | 不可恢复；项目与检测记录会保留 |

备份包里**不含**：个人信息配置（每台设备重填）、缩略图（导入时自动重建）。
建议把备份文件放到网盘/移动硬盘，而不是留在手机里。

**多台设备**：各自独立、互不同步。要在一台新设备上继续，就"导出 → 导入备份"，再填一次个人信息。

## 6. 首次试用清单（3 分钟）

1. 打开首页 → 停在「项目」页；
2. 「+ 新建项目」→ 项目编号 + 房屋名称 → 保存；
3. 项目详情 → 「+ 添加检测记录」→ 选「幕墙立柱」→ 楼层/构件位置/检测面 B → 填 5 个读数 → **最小值应自动算出** → 保存；
4. 「报告」页 → 「+ 新建报告」→ 选一张照片 → 填缺陷类型/工程部位/整改方案 → 绑定该项目 → 提交；
5. 回项目详情 → 「附加 1 份并导出」→ 下载并打开 .docx，确认版式与附页照片方向正常；
6. 我的 → 数据管理 → 导出备份（确认能下载 .zip）；
7. 断网后刷新页面：应用应仍能打开（离线缓存生效）。

## 7. 常见问题

**1）页面一片空白**
按顺序查：
- 地址是不是 `file://` 开头？→ 必须用 `http://`（第 2 节）；
- 按 F12 → Network，看 `app/main.js` 的 `Content-Type`：**必须是 `text/javascript`**，
  若是 `text/plain` 或 404 → 服务器的 `.mjs` MIME 没配（第 2 节）；
- 浏览器 Console 里的红色报错截图发我们（通常是 `Failed to load module script`）。

**2）提示「当前环境没有 IndexedDB（浏览器里请用 https 或 localhost 打开）」**
用 `file://` 打开会这样；某些浏览器的"无痕模式"也会禁用 IndexedDB。换普通窗口 + `http(s)` 地址。

**3）点「导出」时报错**
把顶部黄色提示条的**原文**发我们。v1.0.1 已修复两个会让核心流程中断的问题（导出报 nodebuffer、导入备份报 zip.files）
（旧版本报 `nodebuffer is not supported by this platform`，若见到这句说明用的是旧包）。

**4）改了 `app/product.js` 但手机上没变化**
见 4.4：需要关闭页面重开，并确认「关于 → 离线缓存版本」变了。

**5）iOS 上点"拍照"打不开相机**
浏览器规定 `http://` 页面不能调起相机（需要 HTTPS）。请用「从相册选择」——
先用系统相机拍照，再回来选。要支持直接拍照就需要给站点配 HTTPS。

**6）数据不见了**
本工具没有服务端，数据只在设备上。请回顾：是否清过浏览器数据、是否换过浏览器/设备、
是否长期未打开（iOS 未授权持久化时会清理）。这就是第 5 节强调"定期导出备份"的原因。

**7）能不能多人共用一份数据？**
本期不支持：没有账号体系，也没有服务端存储，每台设备各自独立。
多人协作需要后续版本（或由一人汇总，用"导出/导入备份"传递）。
